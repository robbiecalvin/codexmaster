# Contributing

Before proposing changes, read the README and any repository-specific agent instructions, architecture notes and testing guides.

## Changes

Keep changes focused. Explain the problem, expected behavior and compatibility implications. Preserve existing acceptance criteria and unrelated work. Use synthetic fixtures rather than personal or production data.

## Verification

Run the relevant documented checks in an isolated development environment. Include commands, actual results and any untested behavior in the pull request. Do not weaken tests to obtain a passing result.

## Security

Follow [SECURITY.md](SECURITY.md) for private vulnerability reporting. Never commit credentials or private records.

Contributions are subject to the repository's existing licensing terms; this document does not grant additional rights or promise acceptance.
