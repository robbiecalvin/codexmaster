# Agent instructions

Read [engineering instructions](docs/AGENTS.md), [agent roles](docs/development/modular_agents.md) and [launch acceptance](docs/development/launch_acceptance.md) before modifying the framework. Preserve explicit constraints, evidence requirements and role boundaries. Distinguish proposed architecture from implemented runtime behavior. Validate changed references and configuration; report checks actually performed. Never claim model training or orchestration has been verified without evidence.

## CodexMaster 2.0 development branch

The owner-approved [v2 migration policy](framework/v2/MIGRATION.md) governs this branch. Read it before making changes. Every code modification, including routine or LOW-complexity work, requires prior developer approval of a scoped change plan tied to the current revision. Read-only inspection, planning and authorized checks may proceed automatically. Material scope or risk changes require renewed approval. This supersedes conflicting implicit routine-edit permission in legacy instructions. Preserve project-specific documents and do not merge or deploy without explicit authorization. The complete v2 skill distribution is not yet installed on this branch.
