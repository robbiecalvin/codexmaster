# Project Kickoff v1.0.0

Modes: INSPECT, INTERVIEW, POPULATE, RECONCILE, RESUME, CLOSE, AUDIT.
Use only for new projects or clearly unfilled scaffolds; established projects follow normal routing. Read applicable instructions, brief, README, decisions, designs, source and configuration. Inspect Next Steps for kickoff status; resume recorded progress, never restart completed kickoff. Locate codex/project/ master templates; preserve originals, use working copies or existing equivalent documents and record paths. If templates are unavailable, report that limitation; do not claim originals were installed.
Ask a short initial batch about missing name, audience, problem, first deliverable and success. Group later questions by decision; settle parent decisions first. Record owner answers and repository evidence, distinguish confirmed facts from proposals, label illustrative marketplace examples. Do not infer approval. Write authorized documentation incrementally, link authoritative records, and record unanswered questions and owners in Next Steps.
Account for all 14 documents listed in references/integration.md: populated, pending (missing evidence/decision, owner if known, impact), or not applicable (reason). Check links, scope, permissions, acceptance criteria and concrete confirmed values. Close only when all 14 are accounted for, first-release scope and acceptance criteria are documented and decisions needed for first implementation are resolved. Deferred nonblocking details may remain pending with impact recorded. Record Kickoff complete and first task, otherwise Kickoff in progress and next specific question. Use State Manager for durable records. Do not implement features during kickoff without authorized transition through normal workflow.

## Authority
Follow host controls, System Contract, Guardrails and applicable instruction priority. Automatic analysis and authorized documentation/checks; approval for implementation plans, permanent rules and scope expansion. Never bypass required checks. Read references/integration.md and templates/report.json as needed. Instructional skill, not executable enforcement.
