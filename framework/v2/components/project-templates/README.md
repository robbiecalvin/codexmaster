# Project Templates v1.0.0

Fourteen owner-supplied master documents, preserved byte for byte. Copy `codex/project/` into a new project only after inspecting existing documentation; never overwrite existing working documents. Use Project Kickoff to populate applicable records, preserve master copies, label marketplace examples as illustrative, and record proposed decisions separately from confirmed facts. For established projects reuse equivalent documents and record their paths in Next Steps.

## Kickoff integration
- Start with project identity, audience, problem, first deliverable and success criteria; ask only unresolved questions.
- Record each of the 14 documents in Next Steps as populated, pending or not applicable, with path, evidence, owner and reason as appropriate.
- Keep authoritative requirements in their respective documents; decisions in decisions.md; progress and checkpoints in next_steps.md.
- Check cross-document scope, permissions, acceptance criteria and links. Resolve decisions blocking the first task before marking kickoff complete.
- Do not treat examples as approved requirements or evidence of implementation. Do not load every template for every task; retrieve relevant sections.

## Integration dependency
The original Next Steps link to `../workflow/state_manager.md#save-a-checkpoint` requires the framework workflow documentation or an equivalent mapped reference. The integrated distribution supplies it at codex/workflow/state_manager.md relative to the distribution root. Master templates are in the root codex/project/ directory. Other bracketed project-reference placeholders must be resolved in the target project. No source links have been rewritten.
